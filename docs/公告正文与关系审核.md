# 公告正文、候选审核与关系发布

更新：2026-11-11。工程：`<仓库根目录>`。入口：本机 `http://127.0.0.1:58872/knowledge-graph`，沿用开发账号。

## 操作流程

1. 输入 `600519`，点击“获取资料并构建图谱”。公告来自现有东方财富适配器，无需上传资料。
2. 在“公告正文与候选审核”选择公告，点击“抓取所选公告正文”。保存的 PDF 可下载，页面显示摘要、解析版本、覆盖页数与分段。
3. 点击“使用 DeepSeek 提出候选”，才会发送正文片段并产生模型用量。成功的相同输入复用已有任务；失败或未知结果需点击明确重试。
4. 查看候选的业务类型、计划/否定等语气和逐字引文。点击“定位原文”，核对页码、段落及高亮上下文。填写 3—500 字审核说明，再通过或驳回。
5. 勾选已通过候选，点击“发布选中关系”。发布完成后点“已发布版本”查看图谱。每批选择 1—8 条候选，生成独立版本；历史批次不会被隐式合并。

已发布关系为 `Security → HAS_SOURCE_CLAIM → Claim → SUPPORTED_BY → DocumentVersion`。它表示公告对该证券的来源陈述；“计划召开”不会变成“已召开”。人工审核不构成对现实事件的独立查证。

## 文档版本与定位

浏览器只能提交已采集版本和公告 ID。Java 从固定公告主机 `pdf.dfcfw.com` 下载 PDF，限制响应大小与下载时间。

解析器采用 Apache PDFBox，最多抽取 20 页、10 万字符和 120 段。超出范围会标记不完整，扫描件无文字时提示需要 OCR。

PostgreSQL 保存原始 PDF、SHA-256 与不可变解析 JSON。页段偏移指向对应解析版本的规范文本，单位为 UTF16_CODE_UNITS。旧 `pypdf:` 版本仍可查询；新解析不会覆盖旧版本。

同项目、证券、公告、PDF 摘要及解析版本唯一。`sf_document_catalog` 允许同一文档映射到多个采集版本；文档记录本身保留首次关联版本。

## 候选与证据校验

模型只取得前 6 段、最多 6000 个 UTF-16 单元的引用句段，最多输出 6 条候选；当前提示要求最多 3 条，可靠内容不足可返回空数组。固定格式为：

```json
{"candidates":[{"predicate":"EVENT","object":"原文连续短语","modality":"PLANNED","chunkId":"p1-c1","quote":"从输入句段逐字复制的原文，至少12字符"}]}
```

`predicate` 仅 BUSINESS/PRODUCT/EVENT，`modality` 仅 ASSERTED/PLANNED/NEGATED/UNCERTAIN。服务端要求对象是引用中的连续原文、引用完整存在于模型已输入段，检查长度、枚举、额外字段、重复项及明显的计划/否定翻转。格式整体无效导致任务失败；单项不合格持久化为 INVALID，不能通过审核。校验通过只进入 PENDING，不能自动发布。

这是字面校验与保守语气规则，不是完整语义判定器。审核人仍须确认主体、上下文、事项类型和语气。审核记录保存操作者、理由和时间；同一决定可重复提交，不能反转已锁定决定。驳回与 INVALID 都不能发布。

发布前重新验证候选、文档摘要和采集归属。证据保存文档/候选/抽取版本、页段、引文与偏移、模型/提示/schema版本、审核者和意见。原采集快照的 `bodyStatus=NOT_COLLECTED` 保持原样，它表达采集时的目录状态；正文状态由独立文档记录查询。

## 持久化任务、预算与恢复

Flyway V4 新增下列表，不修改 V1—V3：

| 表 | 职责 |
| --- | --- |
| sf_document_version / sf_document_catalog | 原 PDF、解析版本、来源及目录关联 |
| sf_evidence_job | DOCUMENT/EXTRACTION/PUBLICATION 独立任务、幂等、租约和取消 |
| sf_model_budget | 项目 UTC 每日预占与真实 Token 用量 |
| sf_extraction_run | 固定请求、已发送标记、原始响应、输入摘要与版本 |
| sf_claim_candidate / sf_claim_review | 校验结果、不可变审核决定 |
| sf_claim_publication / sf_claim_outbox | 发布选集、关联版本与投影待办 |

任务状态：QUEUED → RUNNING → SUCCEEDED，非终态可失败或取消。40 秒租约、3 秒心跳、180 秒截止，最多 3 次领取；写入核对状态、执行令牌、租约和截止。PDF/模型/Neo4j 的外部 I/O 不占数据库锁事务。

抽取先预占 22000 Token，每项目默认每日上限 100000。相同进行中或成功输入复用，不重复预占；输入身份包含文档、PDF/解析版本、模型/提示/schema和选段。发送前取消释放额度；发送后无可确认响应则保留预占并标记 UNKNOWN，不自动再次请求。迟到响应仍记录实际成本，但不能写入被取消任务的候选。网络未知结果可由用户明确重新调用，旧额度不会自动清零；尚无供应商账单对账/人工额度调整入口。

模型单次 HTTP 等待 50 秒、响应上限 128 KiB；无自动模型重试。响应持久化后再检查结束原因和候选，恢复已有响应不会再次付费请求。

发布采用 `sf_knowledge_snapshot.kind=REVIEWED_CLAIMS`，先保存 PENDING 和 outbox，在事务外幂等写 Neo4j，再通过执行权校验发布 READY。投影失败有限重试，取消后的迟到投影不开放查询。基础采集缓存只复用 CATALOG。未发布孤立投影的清理和全量灾备重建命令尚未提供。

## API

基础路径 `/api/projects/{project}/knowledge`；Next 代理为 `/api/java/projects/{project}/knowledge`。全部需要项目授权，写接口需要 OWNER 与 CSRF；下表标“入队”的接口必填 8—128 位幂等键，新建 202、复用 200、冲突 409。

| 方法与后缀 | 请求或返回 |
| --- | --- |
| POST /documents | 入队；`{catalogSnapshotId,providerId}`，必须来自 READY 基础采集版本 |
| GET /releases/{catalog}/documents | 该采集版本已保存文档 |
| GET /documents/{id} | 版本、来源、覆盖和页段文本 |
| GET /documents/{id}/pdf | 保存的原始 PDF，attachment、nosniff、private/no-store |
| POST /documents/{id}/extractions | 入队；`{retryFailed:false}`，显式重试为 true |
| GET /documents/{id}/extractions | 抽取版本、状态、选段和实际/预占用量 |
| GET /documents/{id}/candidates | 该文档各次抽取候选及审核状态 |
| POST /candidates/{id}/review | `{decision:"APPROVED"或"REJECTED",reason:"审核说明"}` |
| POST /publications | 入队；`{catalogSnapshotId,candidateIds:[UUID]}` |
| GET /releases/{catalog}/publications | 已发布批次及图谱版本 |
| GET /evidence/jobs 与 /evidence/jobs/{id} | 最近任务或指定任务 |
| POST /evidence/jobs/{id}/cancel | 取消非终态任务 |
| GET /evidence/budget | 项目 UTC 当日 limit/reserved/used |

正文下载、解析和证据校验由 Java Worker 执行。受限代理仅开放上述业务接口，不开放模型原始请求、任意 URL 或 Cypher。

常见错误：DOCUMENT_HAS_NO_TEXT 需要 OCR/其他公告；MODEL_NOT_CONFIGURED 检查服务端配置；MODEL_DAILY_BUDGET_EXCEEDED 为项目额度不足；EXTRACTION_RETRY_REQUIRES_CONFIRMATION 需要明确重试；MODEL_OUTCOME_UNKNOWN 表示不能确定供应商结果，禁止自动重发；CANDIDATE_NOT_APPROVED/CANDIDATE_REVIEW_LOCKED 为审核规则；CLAIM_PROJECTION_UNAVAILABLE 检查 Neo4j。

## 配置、运行与验证

使用 Java 21、Spring Boot、PDFBox、PostgreSQL/Flyway、Next.js/TypeScript 和 Neo4j。模型密钥来自服务端配置。

| 变量 | 默认与含义 |
| --- | --- |
| SIGNALFORGE_EVIDENCE_WORKER_ENABLED | 未设置时跟随 SIGNALFORGE_KNOWLEDGE_WORKER_ENABLED，控制新任务派发 |
| SIGNALFORGE_MODEL_DAILY_TOKEN_LIMIT | 100000，项目 UTC 每日 Token 上限 |
| SIGNALFORGE_DEEPSEEK_API_KEY / MODEL | 服务端密钥与模型名，沿用既有配置 |

重新构建并启动 Java 即可加载 PDFBox。修改配置后重启对应服务。

```powershell
# 在仓库根目录执行
.\scripts\check-backend.ps1
# 三个开发服务已运行时；默认只抓取正文，不调用模型
node verification/javascript/smoke_documents.cjs
# 显式抽取一次，产生模型用量；成功输入可复用
node verification/javascript/smoke_documents.cjs --extract
```

脚本使用本机 Google Chrome 隔离上下文，读取本地开发账号，保留开发库记录和 `.runtime/document-verification` 报告。发布验收必须先在页面审核候选，再执行脚本的 `--verify-publication --candidate UUID`；不会代替用户自动通过新候选。
